# 质量门清单

两道门，**都必须过**才交付。第一道在构建期自动跑（不合格直接中止），第二道是运行时探针。

---

## 第一道：构建期硬断言（`build.py`）

设计原则：**能自动发现的问题，绝不留给人工；能中止的，绝不静默降级。**

| # | 断言 | 不通过的后果 | 为什么必须硬性 |
|---|---|---|---|
| 1 | `id`/`n`/`ty`/`ar` 齐全 | 渲染出空白卡片 | 页面直接显示残缺 |
| 2 | `id` 唯一且为整数 | 卡片与地图图层串条 | 靠 id 关联，重号会点 A 显示 B |
| 3 | `lat`/`lng` **成对**出现 | Leaflet 抛错或点落到 (0,0) | 单个坐标是无效状态 |
| 4 | 经纬度在合法范围 | 点跑到地图外 | 防止手误写成 `1143` 这种 |
| 5 | `loc` 只用 `exact`/`approx`/省略 | 逻辑分支失配 | 拼错（如 `lac`）会被当精确点，**冒充精度** |
| 6 | **每个 `ty` 都被 `categoryGroups` 收录** | 地图上出现无名灰点 | ⭐ 换目的地时新增类名必漏，肉眼几乎发现不了 |
| 7 | 同一类型不被多个分组重复定义 | 配色取决于顺序，不确定 | 配置错误应显式暴露 |
| 8 | **`star:true` 最多一条** | 「唯一锚点」语义失效 | 多于一个五角星，用户不知道哪个是住处 |
| 9 | `star` 条目必须有坐标 | 星标无法落到图上 | 功能静默缺失 |
| 10 | 四档口径互斥、并集为全集 | 统计栏数字对不上 | 用户会据此判断数据可信度 |
| 11 | **来源截图文件真实存在** | 线上详情页静默裂图 | `src` 是相对路径，缺图不报错，只有用户看得到 |
| 12 | `notes.position` 只用 head/tail | 说明块被静默丢弃 | 位置值拼错不会报错 |

同时输出**告警**（不中止，但要看）：

- 出现未识别的字段名 → 多半是拼写错误（`loc` 写成 `lac` 就是靠这条抓到的）。
- `categoryGroups` 里有本次数据没用到的类型 → 可以清理，或说明数据漏了。
- 没有任何 `star:true` → 「以住处为基准」按钮会失效。

### 用法

```bash
python "<SKILL_DIR>/assets/build.py" --trip "trip.json" --check-only   # 只校验
python "<SKILL_DIR>/assets/build.py" --trip "trip.json"                # 校验并生成
```

构建成功会打印口径对账行，**必须自己核一遍**：

```
✓ 已生成 …/index.html
  条目 217 ＝ 精确 113 + 区域近似 70 + 未定位 34 + 不标注 0 ｜ 星标 1 ｜ 类别 11 组 / 46 型
```

> ⭐ **类别数这一项最容易出错。** 每次增删数据，第一件事是看「类别 N 型」有没有变——变了说明引入了新类型名，必须回头确认它已被归组。
>
> **真实案例（开封原版，2026-10-02 复盘发现）**：该页配色表是**硬编码 39 项**，而数据实际有 **46 个 `ty`**，
> 导致 **8 类 16 条**长期落到兜底灰 `#7f8c8d`。**六轮迭代都没人发现**——因为灰色本就是设计好的「杂类色」，
> 看起来「也说得通」。这就是为什么本引擎把它做成**硬断言而非警告**：靠人眼对账，一定会漏。
> 完整记录见该项目目录下 `待办-类别配色.md`。

## 第二道：运行时回归探针（`scripts/probe.py`）

```bash
python "<SKILL_DIR>/scripts/probe.py" --html "<工作目录>/index.html"
```

两种视口（宽屏 1440 / 窄屏 430）各跑一遍，**期望值全部从页面内嵌数据推导**，所以换目的地不用改脚本。

### 覆盖范围（29–30 项 / 视口）

| 组 | 断言 | 说明 |
|---|---|---|
| **A 口径** | 卡片数＝数据条目数；统计栏＝推导值；地图圆点数＝可标注数；星标图层数＝星标条目数；图例非空；每个类别都有显式配色 | 数字全部算出来比对，不看截图 |
| **B 结构** | 清单在独立滚动区内；每张卡片都有复制按钮；初始为占位态；说明块在滚动区内 | |
| **C 折叠** | 把手可见；初始展开；点击后收起且地图不占位；图例一并隐藏；地图区塌陷；文案与 `aria-expanded` 同步；宽屏切单列并限宽；折叠态下功能仍可用；展开后尺寸复原；`invalidateSize` 生效；瓦片已渲染 | 「展开后尺寸复原」是防灰块的关键 |
| **D 交互闭环** | 点卡片开 / 再点关；点圆点开 / 再点关；点空白关；✕ 几何合理且能关；Esc 关 | 用真实事件路径，不用页面内函数直调 |

`TOTAL FAIL = 0` 才算通过。

## 写断言时的三个陷阱（都踩过）

### 1. 期望值算错，不是产品错

本引擎开发过程中，有三次 FAIL 是**断言自己写错了**：

- 圆点数写成「有坐标且非 offmap」的条数，忘了**星标条目渲染成图标而非圆点**，多算 1。
- 用 `getBoundingClientRect()` 和 Leaflet 的 `clientWidth` 比对，差了 2px——`rect` 是 border-box 含边框。
- 断言「来源截图 `img` 在 DOM 里」，但该 `img` 只在选中条目时才注入，初始态本就没有。

**教训**：FAIL 时先怀疑断言，再怀疑产品。断言写错的代价是被误导去改本来正确的代码。

### 2. 假通过：断言恰好满足

`MAP.getSize()` 返回的是**缓存值**。断言「展开后 `getSize()` 等于 DOM 尺寸」时，即使漏写 `invalidateSize()`，缓存值也可能恰好等于期望值 → 假通过。

**解法**：制造差异化输入。折叠期间把地图高度临时改成 200px，展开后断言 `getSize()` 变成了 198 而非旧缓存 255——「修了/没修」结果必然不同，这才算真验证。

### 3. 绕过真实事件路径

直接对 `#map` 派发 click 来测「点空白关闭」，会绕过 `elementFromPoint` 命中的真实元素，**假通过**。

**解法**：用 `elementFromPoint` 取真实背景元素，再对它派发事件。

## 交付前人工自检

自动门管不了这些：

- [ ] 抽查 3–5 条：点开详情，**来源截图能显示**、导航链接（高德/腾讯）能打开，且**地图落点与实际位置一致**
- [ ] 每条带坐标的条目都有**证据留痕**：`rm` 里能读到「腾讯地图：XX店」或「未单独检索到」（方法见 `geo-verification.md`）
- [ ] 手机视口：地图可折叠、清单能独立滚动、卡片文字不被裁切
- [ ] 住处条目已**照实标注**（店名 + 坐标 + 唯一星标 + 距离基准可用）——**默认不打码**
- [ ] 若该文件会对外发布 → 已按 `SKILL.md` 第六节 6.1 处理住处（地址降到路段、去掉个人称呼），且 `star` / 坐标保留
- [ ] 「区域近似」与「未定位」条目数量，在交付说明里**如实告知**用户
- [ ] 素材版权：若来源是他人的社交平台截图，提醒用户公开发布的风险

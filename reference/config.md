# trip.json 配置参考

一份 `trip.json` 描述一个目的地。复制 `examples/kaifeng/trip.json` 改内容即可，**模板本体不用动**。

所有以 `_` 开头的键（如 `_comment`）都会被忽略，仅作注释。

---

## meta —— 身份与文件

| 字段 | 必填 | 说明 |
|---|---|---|
| `slug` | 是 | 英文短名。用作导航链接的 `src`/`referer` 标识（如 `kaifeng-food-map`）。**只用小写字母、数字、连字符**。 |
| `title` | 是 | 浏览器标签页标题。建议「目的地 + 主题 + · 主要片区」。 |
| `h1` | 是 | 页面主标题（正常字色）。 |
| `h1Accent` | 是 | 主标题后跟着色的一段（`·` 之后）。写主要片区。 |
| `data` | 是 | 数据文件名，相对 `trip.json` 所在目录。 |
| `output` | 否 | 输出文件名，默认 `index.html`。 |
| `assetRoot` | 否 | 资源根目录，相对**输出 html 所在目录**。用来校验来源截图是否存在。默认 `.`。 |

```json
"meta": {
  "slug": "kaifeng-food-map",
  "title": "开封美食地图 · 清明上河园 / 鼓楼",
  "h1": "开封美食地图",
  "h1Accent": "清明上河园 / 鼓楼 / 老河大",
  "data": "data.json",
  "output": "index.html",
  "assetRoot": "."
}
```

## theme —— 主题色

| 字段 | 说明 |
|---|---|
| `accent` | 主色。用于按钮、标题强调、卡片选中边框、toast 左条。 |
| `accentDark` | 主色的深一档，用于 hover。 |
| `accentRgb` | 主色的 `R,G,B`（**不带 `rgb()` 包裹**），用于需要透明度的场景（如 `rgba(181,68,58,.14)`）。 |
| `fallbackColor` | 类别未配色时的兜底色。正常情况下不该被用到——构建期会强制全部类别归组。 |

> `accentRgb` 必须与 `accent` 是同一个颜色，否则半透明描边会与实色不符。

## geo —— 地理位置与底图

| 字段 | 必填 | 说明 |
|---|---|---|
| `center` | 是 | `[lat, lng]`。**只是初始视野兜底**——实际渲染会自动 `fitBounds` 到数据范围，所以不必精确，给城市中心即可。 |
| `zoom` | 是 | 初始缩放级别（`center` 生效时用）。 |
| `minZoom` / `maxZoom` | 是 | 缩放范围。国内城市一般 `9` / `18`。 |
| `coordSystem` | 是 | 数据坐标系。高德/腾讯 POI = `gcj02`；GPS 原始 = `wgs84`。**仅作声明与提醒，引擎不做转换**。 |
| `region` | 是 | 目的地城市名，用于 POI 检索时限定范围（如 `开封市`）。 |
| `tileUrl` | 是 | 瓦片模板，须含 `{s}` `{x}` `{y}` `{z}`。 |
| `subdomains` | 是 | 瓦片子域数组。 |

### 常用瓦片源

| 用途 | tileUrl | 坐标系 |
|---|---|---|
| 高德（推荐，国内） | `https://webrd0{s}.is.autonavi.com/appmaptile?lang=zh_cn&size=1&scale=1&style=8&x={x}&y={y}&z={z}` | GCJ-02 |
| 高德卫星 | `https://webst0{s}.is.autonavi.com/appmaptile?style=6&x={x}&y={y}&z={z}` | GCJ-02 |
| OSM（海外） | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` | WGS-84 |

> ⚠️ **坐标系必须匹配**。用 GCJ-02 的 POI 配 WGS-84 的瓦片，整张图会偏移几百米。国内优先高德；海外用 OSM——但 POI 数据源也要换成 Nominatim 之类，见 SKILL.md「地理范围」。
>
> 高德瓦片的 `subdomains` 用 `["1","2","3","4"]`（对应 `webrd01`~`webrd04`）。

## lodging —— 唯一星标（住处 / 集合点）

| 字段 | 说明 |
|---|---|
| `match` | 在数据里定位该条的匹配词（用 `n.indexOf(match) >= 0`）。给一个稳定且不会误匹配的短词，如 `住处`。 |
| `label` | 完整展示名，出现在提示语里。**不要写门牌**。 |
| `short` | 界面上的短称呼，如 `住处`。 |

> 数据里必须**恰好一条**标 `"star": true`，构建期强制校验。没有 star 条目时构建仍可通过（仅告警），但「以住处为基准算距离」按钮会失效。

> ℹ️ **住处标注策略**：默认**照实标**（店名 + 坐标 + 星标），它是距离基准与唯一锚点；
> **只有当这份页面要对外发布时**，才需要处理地址与个人称呼 —— 完整规则见 `SKILL.md` 第六节。
> 坐标与 `star` 始终保留：脱敏不该损伤功能。

## categoryGroups —— 类别归组与配色（关键）

数组，每项：

| 字段 | 说明 |
|---|---|
| `name` | 组名，如「汤包面点」。 |
| `color` | 该组颜色，十六进制。 |
| `types` | 该组包含的类型名数组，**必须与 `data.json` 里的 `ty` 逐字一致**。 |

```json
{ "name": "汤包面点", "color": "#c0392b",
  "types": ["灌汤包", "灌汤包·豫菜", "锅贴", "锅贴·灌汤包"] }
```

**构建期强制**：数据里出现的每个 `ty` 都必须被某个组收录，漏一个直接报错中止。这是防止「地图上出现无名灰点」的闸门——换城市时新增的类别名最容易漏配，肉眼几乎发现不了。

同理，配置里写了但数据没用到的类型会给出告警，提示可以清理。

### 配色建议

- 同类语义用同一色（比如所有汤类都是棕色），别按类型逐一分色。
- 组数控制在 8–12 个：太少分不清，太多图例太长。
- 灰 `#7f8c8d` 留给「杂项」，因为它最不抢眼。**但注意它也是兜底色**——所有类别都归组后，兜底色不会再被用到。

## labels —— 界面短文案

这些是 JS 动态生成的文本，也在页面各处复用。

| 键 | 含义 | 默认 |
|---|---|---|
| `star` | 图例里的星标说明 | 本次住宿 |
| `starBadge` | 卡片角标 | ★ 本次住宿 |
| `starTooltip` | 地图悬浮提示前缀 | ★ 本次住宿 · |
| `starTip` | 详情面板里加粗的那句 | 本次行程住处 |
| `starTipNote` | `starTip` 之后的普通文字 | （地图上唯一的红色五角星标记） |
| `approx` | 区域近似的标签文字 | 区域近似 |
| `approxTip` | 详情面板里的解释 | 该店在地图上无独立 POI… |
| `offmap` | 不标注的标签文字 | 不在地图标注 |
| `offmapTip` | 详情面板里的解释 | 该处为推荐列表中提及的其他… |
| `noLoc` | 未定位标签 | 未定位 |
| `noCalc` | 有坐标但未算距离 | 未算距离 |
| `lodgingBtn` | 工具栏按钮 | 🏨 以酒店为基准算距离 |
| `lodgingUsed` | 已切换后的按钮文字 | 🏨 已用酒店为基准 |
| `lodgingToastBtn` | 提示框里的按钮 | 🏨 改用酒店为基准算距离 |
| `mapbarTitle` | 折叠把手左侧 | 🗺️ 地图 |
| `mapbarCollapse` | 展开态时把手右侧 | 收起 ▲ |
| `mapbarExpand` | 折叠态时把手右侧 | 展开 ▼ |

> 非美食/非住宿场景（如「徒步补给点」），把 `star*` 一系改成「集合点」，`lodging*` 改成「以集合点为基准」，读起来就通了。

## texts —— 页面长文案

**这里的内容按 HTML 原样注入**，可以带 `<b>` `<br>` 等标签。

| 键 | 位置 | 说明 |
|---|---|---|
| `sub` | 标题下方 | 来源说明、口径说明、住宿提示。**建议写清「实心＝精确、空心＝近似」，并提醒可点开来源截图核对。** |
| `hint` | 地图下方 | 操作说明。桌面端可见，窄屏自动隐藏。 |
| `placeholder` | 搜索框 | 占位提示。 |
| `detailHome` | 详情面板初始态 | 未选中时显示什么。 |
| `statsOffmap` | 统计栏 | 「不标注」那一项的标签，如「其他酒店不标注」。只有在存在 `offmap` 条目时才显示。 |
| `statsNote` | 统计栏 | 额外说明，如「已合并重复 <b>9</b> 条」。**留空即不显示**——如果没做过去重，就别写。 |
| `mapfail` | 地图区 | 瓦片加载失败的提示。要说明「数据不受影响，仍可在清单查看」。 |

## notes —— 说明块

数组，每项：

| 字段 | 说明 |
|---|---|
| `position` | `"head"` = 清单**上方**；`"tail"` = 清单**末尾**（滚到底才看到）。 |
| `section` | 可选的分组小标题，如「数据说明与核验」。 |
| `title` | 折叠块的标题（默认收起）。 |
| `items` | 字符串数组，每条渲染成 `<li>`，**支持 HTML**。 |

**摆放建议**：
- `head` 放「速览 / 高频推荐」——用户一眼想看的。
- `tail` 放「数据来源 / 校验方式 / 已知局限 / 免责」——需要时才查的。

> 位置很影响体验：手机端地图 + 说明块占满屏，清单就被挤下去了。所以「长说明」一律放 `tail`。

```json
{
  "meta": { "slug": "chengdu-food-map", "title": "成都美食地图 · 玉林 / 建设路",

            "data": "data.json" },
  "theme": { "accent": "#b5443a", "accentDark": "#9c382f", "accentRgb": "181,68,58" },
  "geo": { "center": [30.6598, 104.0657], "zoom": 13, "minZoom": 9, "maxZoom": 18,
           "coordSystem": "gcj02", "region": "成都市",
           "tileUrl": "https://webrd0{s}.is.autonavi.com/appmaptile?lang=zh_cn&size=1&scale=1&style=8&x={x}&y={y}&z={z}",
           "subdomains": ["1","2","3","4"] },
  "lodging": { "match": "全季", "label": "全季酒店(成都春熙路店)", "short": "住处" },
  "categoryGroups": [
    { "name": "火锅串串", "color": "#c0392b", "types": ["火锅", "串串"] },
    { "name": "小吃面食", "color": "#e67e22", "types": ["小吃", "面食", "抄手"] },

  ],
  "labels": { "star": "本次住宿", "starBadge": "★ 本次住宿", "starTooltip": "★ 本次住宿 · ",
              "starTip": "本次行程住处", "starTipNote": "（地图上唯一的红色五角星标记）",

  "notes": [
    { "position": "tail", "section": "数据说明",
      "title": "坐标来源与已知局限",

```

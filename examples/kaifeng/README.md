# 开封样例配置

这是「开封美食地图」的完整配置，也是本引擎的**参照样例**——包含全部可配项，换目的地时逐项改写即可。

| 文件 | 说明 |
|---|---|
| `trip.json` | 完整配置：标题、主题色、地图与瓦片源、11 个类别组（覆盖 46 个类型）、文案、说明块 |
| `data.json` | 217 条数据（精确 113 + 区域近似 70 + 未定位 34） |

## 试跑

```bash
python ../../assets/build.py --trip trip.json --check-only     # 只校验
python ../../assets/build.py --trip trip.json --out ./index.html
```

## 注意

本目录**不含来源截图**（`图片素材/原图/`，约 14MB，未随技能打包）。所以：

- `--check-only` 仅检查数据与配置，不涉及图片。通过与否以当前运行结果为准。
- **直接生成时会出现一条告警**：「215 条来源图片引用全部找不到……若这是配置样例可忽略」——这是预期行为，不是错误。生成出的 `index.html` 除详情页截图不显示外，功能完全正常。

要连截图一起验证，把 `图片素材/原图/` 放到输出 html 同级目录即可，成功时会打印「已校验 215 张来源截图，全部存在」。这里的 215 是引用数，涉及 46 个不同图片文件；仍需人工抽查图片是否对应条目。

## 关于住处（本样例已**完全泛化**）

`data.json` 里住处那条（`star: true`，`id: 70`）已做**双重处理**：

| 项 | 处理 |
|---|---|
| 店名 | 泛化为「住处（示例）」 |
| 地址 | 降到路段级（「鼓楼区一带」） |
| 来源 | 写「行程主人提供」 |
| **坐标** | **偏移为演示值**——落在本市中心附近，但不再指向任何真实地点 |

原因：本样例会**随技能一起公开**，因此单独选择将名称与坐标泛化。这只说明公开演示的状态；[SKILL.md](../../SKILL.md) 默认面向用户生成自用地图，保留真实坐标来保证距离准确。

为什么要连坐标一起动：店名泛化而坐标不动，点开星标仍能从底图反查到具体门店，等于没脱敏。
示例数据的作用是**演示功能**（星标 + 距离基准），不需要指向真实地点。

⚠️ **别把这当成默认要求。** 你自己做的时候，住处**照实标更好用**（店名 + 地址 + 坐标，距离和星标才准）——
只有确定这份页面要对外发布时，才按 `../../SKILL.md` 第六节的清单处理。规则见该节 6.1 / 6.2。

## 换目的地怎么改

1. 复制 `trip.json` 到新目录，改 `meta`（slug / 标题 / 数据文件名）
2. 改 `geo`（center 给城市中心即可，实际会自动适应数据范围；**region 改成目的地城市**）
3. 改 `categoryGroups`——**这是最容易忘、后果最严重的一项**：目的地变了，类别名一定不同，漏配的类别在地图上会变成无名灰点，且构建期会直接报错中止
4. 改 `lodging`（住处匹配词）与 `labels`/`texts`（文案）
5. 备好 `data.json`，用 `--check-only` 反复校验直到 0 错

字段细节见 [配置字段](../../reference/config.md) 与 [数据字段](../../reference/data-schema.md)。原创内容许可见 [LICENSE.md](../../LICENSE.md)。
